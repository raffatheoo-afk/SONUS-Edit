PROMPT MESTRE — SONUS EDIT
Data de referência: 30/09/2026

============================================================
1. IDENTIDADE DO PROJETO
============================================================

Projeto: SONUS Edit
Plataforma inicial: Android
Package: com.sonusstudios.sonusedit
Base inicial: 0.1.0 / versionCode 1

SONUS Edit é um aplicativo NOVO e separado do SONUS principal.
O editor existente dentro do SONUS principal permanece como uma ferramenta básica/plugin.
SONUS Edit será o produto completo e especializado em criação e edição de vídeos musicais.

NÃO confundir os projetos:
- SONUS principal: com.sonusstudios.streampulse
- SONUS Edit: com.sonusstudios.sonusedit

A criação deste projeto NÃO faz parte da atualização code122 do SONUS.
Nenhuma alteração no SONUS principal deve ser aplicada apenas por existir este projeto.

============================================================
2. VISÃO DO PRODUTO
============================================================

O objetivo não é copiar CapCut ou criar apenas uma timeline vazia.
O grande diferencial é AUTOMÁTICO PRIMEIRO, MANUAL DEPOIS.

Fluxo principal:

MÚSICA + FOTOS/VÍDEOS + ESTILO
-> SONUS Edit analisa e monta o vídeo
-> letra sincronizada aparece automaticamente quando encontrada
-> cortes/transições/movimento seguem o ritmo
-> usuário recebe um primeiro vídeo pronto
-> depois pode refinar tudo manualmente na timeline
-> exporta

O projeto criado automaticamente deve ser o MESMO tipo de projeto usado pelo editor manual. Nunca criar dois motores separados.

============================================================
3. FONTES DE MÚSICA
============================================================

1) SONUS Stream
2) música local do aparelho
3) áudio recebido por compartilhamento Android
4) áudio extraído/importado de vídeo quando essa função for implementada

Quando uma faixa vier do SONUS Stream, receber inicialmente apenas trackId e parâmetros de trecho. Nunca transportar segredo ou URL privada permanente via deep link.

============================================================
4. INTEGRAÇÃO COM SONUS
============================================================

Contrato inicial:
sonusedit://create?source=sonus&trackId=TRACK_ID&startMs=0&durationMs=30000

SONUS package:
com.sonusstudios.streampulse

SONUS Edit package:
com.sonusstudios.sonusedit

SONUS deve abrir o SONUS Edit por Intent explícito quando essa integração for autorizada no futuro.

O SONUS Edit deve:
1. receber trackId;
2. validar entrada;
3. criar projeto provisório;
4. buscar metadados no backend SONUS;
5. obter acesso autorizado/temporário ao áudio quando necessário;
6. procurar letra sincronizada;
7. abrir o editor.

NUNCA colocar em URI:
- senha
- token Firebase
- token pCloud
- segredo de backend
- URL privada permanente

Android App Links HTTPS só devem ser ativados quando houver domínio real controlado e assetlinks.json publicado.

============================================================
5. LETRAS SINCRONIZADAS — FUNÇÃO CENTRAL
============================================================

A experiência desejada:

O usuário escolhe uma música como uma faixa do Gusttavo Lima.
O SONUS Edit lê título, artista, álbum e duração.
Busca automaticamente letra sincronizada.
Se a correspondência for boa, a letra entra automaticamente.
Se não encontrar ou houver dúvida, mostrar uma lupa para busca manual por música/artista.

Provider inicial:
LRCLIB por interface LyricsProvider.

Nunca acoplar a UI diretamente ao LRCLIB. Deve ser possível adicionar/trocar providers depois.

Fallbacks:
1. letra já associada à faixa/projeto;
2. LRC local;
3. cache local;
4. busca automática;
5. busca manual;
6. abrir Lyricsify como fallback externo, sem depender de scraping/API privada não documentada;
7. importar LRC;
8. editor/sincronizador manual.

Se o usuário selecionar só um trecho da música, por exemplo 00:45 até 01:15:
- pegar apenas linhas correspondentes;
- subtrair 45 segundos dos timestamps;
- legenda começa sincronizada no tempo zero do vídeo.

Aceitar arquitetura para:
- LRC line-sync;
- word-sync quando disponível;
- karaoke progressivo;
- duas linhas (atual/próxima);
- overlapping vocals futuramente.

============================================================
6. MODOS AUTOMÁTICOS
============================================================

Criar inicialmente estes conceitos:

A) LYRIC VIDEO
Foco em letra, capa/fundo, partículas, movimento e tipografia.

B) BEAT EDIT
Cortes e transições guiados por batidas/onsets.

C) CINEMATIC
Movimentos suaves, cortes menos agressivos, fades e tipografia elegante.

D) VISUALIZER
Capa, waveform/espectro, partículas e letra opcional.

E) SHORT / REEL
Projetos de 15s, 30s, 60s e duração personalizada; vertical por padrão.

F) SONUS ARTIST
Recebe faixa do SONUS Stream com capa/metadados já prontos e cria conteúdo para divulgação.

Auto Edit deve produzir uma timeline normal totalmente editável.

11. MOTOR DE MÍDIA
============================================================

Base principal:
Jetpack Media3 Transformer / Composition.

Arquitetar por interfaces:
- ProjectCompiler
- PreviewEngine
- ExportEngine
- BeatAnalysisEngine
- WaveformEngine
- LyricsTimingEngine
- AutoEditEngine

FFmpeg é permitido como ferramenta especializada/fallback, mas NÃO deve ser o único motor nem bloquear UI.

REGRA CRÍTICA:
Nunca executar conversão, cópia pesada, decode, waveform, análise de batida ou FFmpeg na Main thread.

Qualquer operação longa:
- background dispatcher apropriado
- progresso real
- cancelamento
- limpeza de temporários
- tratamento de erro

17. REGRAS PARA O DESENVOLVIMENTO
============================================================

1. Mudanças pequenas e verificáveis.
2. Não reescrever módulos estáveis sem necessidade.
3. Antes de alterar arquitetura central, explicar impacto.
4. Cada engine deve ficar atrás de interface quando houver risco de troca futura.
5. Não declarar função pronta sem teste real.
6. Não declarar build green sem build real.
7. Proteger contra regressões.
8. Nenhuma tarefa pesada no Main thread.
9. Preservar arquivo original do usuário.
10. Erros precisam ser amigáveis; exception crua vai para log, não para a interface.
11. Cancelamento precisa cancelar trabalho real, não somente fechar popup.
12. Função automática deve resultar em projeto manualmente editável.
